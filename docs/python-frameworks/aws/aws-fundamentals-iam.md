# AWS Fundamentals & IAM for Python Developers

> This guide introduces Amazon Web Services (AWS) from a Python backend engineer's perspective, exploring Boto3, Identity and Access Management (IAM), policies, and security credentials.

---

# 1. What is AWS & What is Boto3?

## Interview Question

**What is AWS, what is Boto3, and what happens under the hood when a Python application makes an AWS call?**

---

### Answer

**AWS (Amazon Web Services)** is the world's largest cloud computing platform, offering over 200 managed services (storage, compute, databases, messaging, and AI).

**Boto3** is the official AWS SDK (Software Development Kit) for Python.

When your Python code executes:

```python
import boto3

s3 = boto3.client('s3')
s3.upload_file('document.pdf', 'my-bucket', 'document.pdf')
```

Under the hood:
1. Boto3 does **not** open a proprietary database socket.
2. Every AWS service is an **HTTP/HTTPS REST API**.
3. Boto3 reads the parameters, signs the HTTP request cryptographically using **AWS Signature Version 4 (SigV4)** with your secret key, and sends an HTTPS `PUT` request to `https://my-bucket.s3.amazonaws.com/document.pdf`.
4. AWS authenticates the signature, evaluates permissions, executes the action, and returns an XML or JSON response, which Boto3 parses into a standard Python dictionary.

# 2. IAM: The Security Foundation

## Interview Question

**Explain the difference between an IAM User, an IAM Role, and an IAM Policy. Why should production servers never use static Access Keys?**

---

### Answer

AWS security revolves around **IAM (Identity and Access Management)**:

```
┌────────────────────────────────────────────────────────┐
│                       IAM Policy                       │
│    (JSON document defining permissions: WHO can do WHAT)│
└────────────────────────────────────────────────────────┘
                    │                   │
             Attached to          Assumed by
                    ▼                   ▼
┌────────────────────────┐  ┌────────────────────────┐
│        IAM User        │  │        IAM Role        │
│   (Human or Legacy App)│  │ (EC2, ECS, or Lambda)  │
│   • Static Access Key  │  │ • Temporary, Auto-     │
│   • Never in Production│  │   Rotating Credentials │
└────────────────────────┘  └────────────────────────┘
```

---

### 1. IAM Policy (The Rules)

A policy is a JSON document that declares permissions:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowS3UploadsOnly",
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:GetObject"
            ],
            "Resource": "arn:aws:s3:::my-company-invoices/*"
        }
    ]
}
```

**Principle of Least Privilege**: Never grant `s3:*` or `AdministratorAccess`. Grant only the specific actions (`s3:PutObject`) on the specific resource needed.

---

### 2. IAM User vs IAM Role: The Critical Production Difference

| Feature | IAM User | IAM Role |
|---|---|---|
| **Identity Type** | Permanent identity (e.g. `developer-alice`) | Temporary identity assumed by compute resources |
| **Credentials** | **Static Access Key ID + Secret Access Key** | **Temporary credentials generated by AWS STS** |
| **Expiration** | Never expires unless manually rotated | **Automatically rotated every 1 to 6 hours** |
| **Leak Risk** | Extreme: If committed to Git, attacker owns your account | Minimal: Cannot be easily stolen outside the instance |
| **Best For** | Local CLI development | **EC2, Docker (ECS), Kubernetes (EKS), Lambda** |

> **Senior Interview Rule**: In production, your Python backend running on EC2 or ECS should **never** have static access keys configured. It should assume an **IAM Role** attached to the instance profile. Boto3 fetches and rotates temporary credentials automatically from the instance metadata service!

# 3. Boto3 Architecture: Client vs Resource vs Session

## Interview Question

**What is the difference between a Boto3 Client and a Boto3 Resource? When would you use each?**

---

### Comparison: Client vs Resource

```python
import boto3

# 1. BOTO3 CLIENT (Low-level, 1:1 mapping with AWS API)
s3_client = boto3.client('s3')
response = s3_client.list_objects_v2(Bucket='my-bucket')
# Returns a raw Python dictionary: {'Contents': [{'Key': 'file.pdf', ...}], ...}

# 2. BOTO3 RESOURCE (High-level, Object-Oriented)
s3_resource = boto3.resource('s3')
bucket = s3_resource.Bucket('my-bucket')
# Returns rich Python objects with helper methods:
for obj in bucket.objects.all():
    print(obj.key, obj.size)
```

---

### Which one should you use?

| Criteria | `boto3.client` (Recommended) | `boto3.resource` (Legacy) |
|---|---|---|
| **Service Coverage** | **100% of all AWS services** | Only ~10 services (S3, SQS, DynamoDB, EC2) |
| **Feature Updates** | Immediate (Generated automatically from service specs) | Stale (AWS rarely adds new features to resources) |
| **Response Format** | Raw Python dictionaries | Python class instances |
| **Production Recommendation**| **Use `client` for all new code** | Use only for simple S3 object iteration |

AWS has officially ceased adding new features to Boto3 resources. Modern enterprise backend code uses **`boto3.client`**.

# 4. The AWS Default Credential Provider Chain

## Interview Question

**When you call `boto3.client('s3')` without passing any arguments, how does Boto3 find your credentials? In what exact order does it look?**

---

### Answer

Boto3 searches for credentials across multiple locations in a strict, deterministic sequence:

```
1. Explicit Arguments passed to Session:
   boto3.Session(aws_access_key_id="...", aws_secret_access_key="...")
   │
   ▼ (If not found)
2. Environment Variables:
   AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN
   │
   ▼ (If not found)
3. Shared Credentials File:
   ~/.aws/credentials (and ~/.aws/config)
   │
   ▼ (If not found)
4. AWS ECS Container Credentials:
   (Read from container environment if running in Docker on ECS)
   │
   ▼ (If not found)
5. EC2 Instance Metadata Service (IMDSv2):
   (Read from http://169.254.169.254/latest/meta-data/iam/security-credentials/)
```

If Boto3 checks all 5 locations and finds nothing, it raises `botocore.exceptions.NoCredentialsError`.
